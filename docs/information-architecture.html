03

What is missing, in order of what it costs

Not everything on a standard checklist belongs to this house — some of it is deliberately absent, and some of it is absent because nobody has built it yet. These are the second kind, and the first kind is stated plainly underneath so the two never get confused.

Blocks a purchase

  • No promo / discount field. The folding checkout asks who, where and what, and never offers a code. A campaign that mails one has nowhere to spend it.
  • No checkout failure states. Validation errors exist on the field; a declined payment, an invalid code and an item going out of stock mid-checkout do not.
  • No confirmation page. The bag hands off to the account host, so there is no order number, summary or account-creation prompt on this side of the door.
  • No shipping estimate in the bag. One line of copy says made-to-order; there is no cost shown before the handoff.

Blocks a browse

  • No filtering or sorting on the index. /eyewear is six houses in a fixed order. At six that is a feature; at twenty it is a wall.
  • No search results page. Search is an overlay only — there is no linkable /search?q=, so a result cannot be shared or bookmarked.
  • No recently viewed, no complete-the-look. You may also like is the only recommendation surface.
  • No journal, FAQ or size guide. Three content rooms the footer of a storefront this size normally has. Fit & Care carries part of the sizing job.
  • No cookie or privacy-preferences UI. The privacy policy is written; nothing asks.

Absent on purpose — do not "fix" these

  • No announcement bar. A strip of promotional type above a wordmark is the one element that makes a luxury header look rented. If something must be announced, it is a line in the menu overlay.
  • No mega menu. The overlay is four doors set large. Thirteen destinations in a hover panel was the storefront's shape, and it was deliberately cut — see the note in lib/navigation.ts.
  • No account dashboard of our own. Login, signup, password reset, payment methods and addresses live on account.arianoir.com. /access is the branded door and /desk is the reading room; the credential step is the host's, on purpose.
  • No wishlist account-side. /held is localStorage and says so. That is a decision about not asking for an account before someone has decided, not a missing feature.
  • No maintenance page. A static host with atomic deploys has nothing to put behind one.
  • No quick add on the card. Every frame has four to eight colourways; a quick-add button that cannot ask which one is a button that adds the wrong thing.
